------------------------------------------------------------------------
RESUMEN GENERAL
------------------------------------------------------------------------
Un único formulario web recibe leads para DOS unidades de negocio (A y B).
Cada unidad tiene su propio equipo de vendedores divididos en categorías:
  - Expert  (Prioridad 1) → recibe 3 leads por ciclo
  - Senior  (Prioridad 2) → recibe 2 leads por ciclo
  - Junior  (Prioridad 3) → recibe 1 lead por ciclo

------------------------------------------------------------------------
¿CÓMO SE IDENTIFICA LA UNIDAD DE NEGOCIO?
------------------------------------------------------------------------
El formulario web recibe un parámetro en la URL que indica la unidad:

  Unidad A → https://360.cober.online/afiliaciones?u=A
  Unidad B → https://360.cober.online/afiliaciones?u=B

El parámetro "u" se incluye como campo oculto en el POST del formulario
y el backend lo usa para determinar a qué equipo asignar el lead.

------------------------------------------------------------------------
FASE 1: CALENTAMIENTO DIARIO (Mínimo 3 leads por vendedor)
------------------------------------------------------------------------
Al inicio de cada día, TODOS los vendedores activos (de ambas unidades)
deben recibir al menos 3 leads antes de que se active el sistema 3-2-1.

REGLA: Si algún vendedor activo tiene menos de 3 leads asignados HOY,
el sistema distribuye en Round Robin simple entre TODOS los vendedores
que aún no completaron su mínimo de 3, alternando entre Unidad A y B.

  Ejemplo con 2 vendedores por unidad (4 vendedores en total):
  Vendedor A1 (Unidad A), A2 (Unidad A), B1 (Unidad B), B2 (Unidad B)

  Lead  1 → A1  (0/3 → 1/3)
  Lead  2 → B1  (0/3 → 1/3)
  Lead  3 → A2  (0/3 → 1/3)
  Lead  4 → B2  (0/3 → 1/3)
  Lead  5 → A1  (1/3 → 2/3)
  Lead  6 → B1  (1/3 → 2/3)
  Lead  7 → A2  (1/3 → 2/3)
  Lead  8 → B2  (1/3 → 2/3)
  Lead  9 → A1  (2/3 → 3/3) ✅ completo
  Lead 10 → B1  (2/3 → 3/3) ✅ completo
  Lead 11 → A2  (2/3 → 3/3) ✅ completo
  Lead 12 → B2  (2/3 → 3/3) ✅ completo
  ← TODOS tienen 3/3 → SE ACTIVA EL SISTEMA 3-2-1 →

NOTA: Si un vendedor nuevo se activa a mitad del día, vuelve a la
fase de calentamiento hasta completar sus 3 leads mínimos del día.
NOTA: El contador diario se resetea automáticamente a medianoche (00:00).

------------------------------------------------------------------------
FASE 2: SISTEMA 3-2-1 POR CATEGORÍA (Distribución ponderada)
------------------------------------------------------------------------
Una vez que TODOS los vendedores activos tienen sus 3 leads mínimos,
se activa el sistema completo de distribución por categoría:

  PASO 1 → Determinar a qué UNIDAD le toca (Round Robin entre A y B)
  PASO 2 → Dentro de esa unidad, aplicar la secuencia 3-2-1 por categoría
  PASO 3 → Dentro de esa categoría, elegir al vendedor por Round Robin

Secuencia cíclica dentro de cada unidad:
  [Expert, Expert, Expert, Senior, Senior, Junior] → se repite infinito

  Ejemplo con 6 leads consecutivos para Unidad A (post-calentamiento):
    Lead 1 (Unidad A) → Expert A
    Lead 2 (Unidad A) → Expert A
    Lead 3 (Unidad A) → Expert A
    Lead 4 (Unidad A) → Senior A
    Lead 5 (Unidad A) → Senior A
    Lead 6 (Unidad A) → Junior A  ← fin de ciclo, vuelve a Expert A

------------------------------------------------------------------------
REGLAS DE EXCEPCIÓN (se aplican antes de cualquier asignación)
------------------------------------------------------------------------
Los siguientes leads NO se asignan a ningún vendedor:

  1. DUPLICADO: Si el email o teléfono ya existe en la base de datos.
     → Estado: "Dato repetido". Se cotiza pero no se asigna.

  2. MAYOR DE 65 AÑOS: Si el titular tiene más de 65 años.
     → Estado: "Fuera de edad". No se cotiza ni se asigna.

------------------------------------------------------------------------
TABLAS DE BASE DE DATOS NECESARIAS (nuevas)
------------------------------------------------------------------------

  1. unidades_negocio
     - id
     - nombre (ej: "Unidad A", "Unidad B")
     - activa (1/0)

  2. leads_diarios_vendedor
     - id
     - vendedor_id (FK users.id)
     - fecha (DATE)
     - total_leads_hoy (INT)         ← cuántos leads recibió hoy
     - calentamiento_completo (BOOL) ← 1 si ya tiene >= 3 leads hoy
     - UNIQUE KEY (vendedor_id, fecha)
     → Se incrementa con cada asignación. Se resetea a medianoche.

  3. distribucion_round_robin (modificar la existente)
     - Agregar columna: unidad_negocio_id

  4. users (modificar la existente)
     - Agregar columna: unidad_negocio_id

------------------------------------------------------------------------
CONSIDERACIONES TÉCNICAS
------------------------------------------------------------------------

  - El contador diario debe resetearse con un cron job a las 00:00 hs.
    Ejemplo con node-cron: '0 0 * * *'

  - Toda la lógica de asignación debe estar dentro de una transacción
    SQL (START TRANSACTION / COMMIT / ROLLBACK) para evitar condiciones
    de carrera si dos leads llegan al mismo tiempo.

  - Si una unidad no tiene vendedores activos, el sistema debe asignar
    a la otra unidad como fallback (igual que el sistema actual).

  - Si una categoría no tiene vendedores, el sistema cae al vendedor
    con menor carga de cualquier categoría (comportamiento actual).
